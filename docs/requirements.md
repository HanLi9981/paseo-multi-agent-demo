## 1. 项目概述

一个单页待办事项（Todo）应用，以单个 `index.html` 文件承载全部 HTML、CSS 与 JavaScript，
无构建步骤、无外部依赖、无后端服务、数据仅存于浏览器 `localStorage`。

## 3. 本次已确认的新增需求

> 确认日期：2026-10-29。来源：用户逐项采纳项目经理（Project Manager Agent）的建议方案。

### 3.1 任务类型（R-01）

| 项目 | 结论 |
|---|---|
| 字段名 | `type` |
| 取值 | `'personal'`（个人）/ `'public'`（公共） |
| 默认值 | **`'personal'`** |
| 可选时机 | **仅新增任务时选择**；创建后**不可修改** |
| 展示 | 列表项显示中文徽章「个人」/「公共」 |
| 配色 | 个人 = **蓝色**；公共 = **紫色** |
| **语义界定** | **纯本地标记**。不涉及多用户、不涉及共享、不涉及同步。见 3.6 |

### 3.2 紧急程度（R-02）

| 项目 | 结论 |
|---|---|
| 字段名 | `priority` |
| 取值 | `'urgent'`（紧急）/ `'normal'`（一般）/ `'low'`（不急） |
| 默认值 | **`'normal'`** |
| 可选时机 | **仅新增任务时选择**；创建后**不可修改** |
| 展示 | 列表项显示中文徽章「紧急」/「一般」/「不急」 |
| 配色 | 紧急 = **红色**；一般 = **黄色**；不急 = **灰色** |

### 3.3 完成状态视觉强化（R-03）

现状（F-23）已完成「文字变灰 + 删除线」。本次扩大为**整行灰化**：

| 元素 | 已完成时的目标样式 |
|---|---|
| 文字 `.text` | 灰色 `var(--text-light)` + `line-through`（保持现状） |
| 整行 `li` 背景 | 浅灰（如 `#f9fafb`）替代白色 |
| 整行 `li` 边框 | 更浅灰（或降低不透明度） |
| 类型/紧急度徽章 | 降低不透明度（约 `0.55`）并灰度化 |
| 删除按钮 | 降低不透明度（约 `0.65`），`:hover` 时恢复为 `1` |
| 取消完成后 | 以上全部**完全恢复**原有样式 |

约束：**不得**通过改变 `completed` 以外的判定逻辑实现；不得影响未完成项样式。

### 3.4 新增表单布局（R-04）

- 在现有 `.input-row` **下方新增一行**放置两个选择控件（类型、紧急程度）
- 移动端（`max-width: 400px`）下不得横向溢出
- 现有输入框 + 「添加」按钮所在首行结构与行为保持不变

### 3.5 数据模型变更（R-05）

```js
// 变更后单条记录
{
  id:        number,                          // 数值型，向后兼容旧数据
  text:      string,
  completed: boolean,
  type:      'personal' | 'public',           // 新增
  priority:  'urgent' | 'normal' | 'low'      // 新增
}
```

- 存储键名保持 `'todo-list-data'` **不变**
- 不新增存储键、不引入版本号外层包装、不做多分区存储

### 3.6 「公共」语义的明确界定（重要）

| 理解 | 是否本次范围 | 说明 |
|---|---|---|
| **A. 纯标记**：任务带「公共」标签，仅在本机显示 | ✅ **是本次范围** | 仅多一个字段 + 徽章 |
| **B. 多人共享**：多用户共同查看/管理同一批公共任务 | ❌ **明确排除** | 需后端、账号、认证、同步、冲突处理，属架构级变更 |

**本次明确采用 A。** 当前系统数据仅存在于单个浏览器的 `localStorage`，
不存在「其他用户」概念，任何跨用户共享能力均**不在本次范围**。

## 4. 旧数据兼容性要求（R-06）

现有 `localStorage` 中已保存的条目仅有 `{id, text, completed}`，缺少 `type` / `priority`。

| 编号 | 要求 |
|---|---|
| R-06-1 | 加载旧数据时**必须**归一化：缺失 `type` → `'personal'`，缺失 `priority` → `'normal'` |
| R-06-2 | 归一化采用**运行时兜底**：**不得**在加载瞬间立即写回 `localStorage` |
| R-06-3 | 归一化后的值在下一次正常 `save()` 时自然持久化 |
| R-06-4 | 旧数据加载后**不得**报错、不得丢失条目、不得出现 `undefined` 徽章 |
| R-06-5 | 非法取值（不在枚举内，如 `type: 'x'`）按默认值处理 |
| R-06-6 | 保持 F-15 行为：整体 JSON 损坏或非数组时回退空数组 |
| R-06-7 | `STORAGE_KEY` 不得变更 |

## 5. 附带修正项（R-07）

### 5.1 id 唯一性

现状 `id: Date.now()` 在同一毫秒内连续新增两条会产生相同 `id`，导致删除误伤。

- 要求：新增时保证 `id` 唯一
- 约束：**保持数值型**（`typeof id === 'number'`），以兼容旧数据与现有 `Number(li.dataset.id)` 解析
- 做法：检测碰撞并递增，而非改用字符串或 UUID

### 5.2 其他既有行为保持

- F-08 空输入拦截逻辑保持不变
- F-12 Enter 快捷键保持不变
- F-03 `maxlength="200"` 保留
- F-18 `textContent` 渲染方式保留（不得改为 `innerHTML` 拼接用户文本）
- F-17 统计逻辑与显示文案**不改**

## 7. 明确排除的非目标（本次不做）

以下能力**不在本次范围**，开发与测试均不得实现或顺带引入：

- 多用户共享、账号体系、登录、权限、公共任务的后端同步
- 云端存储、跨设备同步
- 筛选、排序、分组（按类型或紧急度）
- 搜索
- 统计区扩展（如「公共：N」「紧急：N」）
- 编辑已有任务的类型或紧急程度
- 编辑任务文本、拖拽排序、批量操作、撤销/重做
- 截止日期、标签、子任务、附件
- 导入/导出/备份
- 主题切换、暗色模式
- 引入任何第三方依赖、构建工具、框架
